## 验证与完成

- 优先修改既有 owning tests 和 durable docs；不为 helper 实现细节新增低价值测试或平行文档。
- 运行与风险和 touched ownership 相称的最小检查；局部检查不得描述成全仓库通过，无法运行的
  检查必须说明原因。
- 纯说明性注释或文档修改通过内容核对验证；仅在可执行示例、doctest 或运行行为受影响时运行
  对应测试。测试层级和回归触发条件遵循仓库唯一验证 owner，Skill 和 adapter 不另设相反门槛。
- 当 owning acceptance 已有与风险相称的证据，且本次变更没有继续产生直接 orphan、stale
  reference 或未验证 contract 时，停止重复搜索、测试和 review；不新增只用于再次确认完成状态的
  审计循环。
- 区分修改前已有失败和本次新增失败；没有基线证据时不要猜测归因。
- behavior、ownership、contract、artifact、default 或 workflow semantics 变化时更新真实长期
  owner，具体完成标准见下文；现有文档仍准确时明确说明无需更新。
- 完成修改时报告 behavior change、public/protected surface、tests、durable docs、保留结构和
  deferred risks，并列出实际验证命令、结果、未验证范围及已知偏差。结构精简还应报告任务规则要求的前后阅读成本指标。
- 结构检查不能替代内容核对；按本次影响沿关键入口核对实际调用、接口、公式、流程和行为证据。
  不能凭文件存在、链接有效、修改过 Markdown 或结构检查通过宣称内容一致。

## 文档完成标准

- 修改前读取适用目录规则，通过仓库文档入口及代码路径映射按本次影响选读；先读主入口，
  带锚点只读对应章节，再沿链接追踪受影响事实，不要求命中文档全文必读或全部修改。
- 每个维护中的核心模块须有实质说明及实现路径定位；紧密相关文件可共用文档。覆盖按真实维护
  职责确定，包含源码包、子包和独立模块，不固定目录数量或旧布局；新增、迁移、拆分或合并职责时
  同步登记，不能留下覆盖缺口。既有映射是唯一路由，不另建平行职责清单。
- 职责、实际依赖、接口、方程、约化、闭合、离散、状态所有权、执行流程或持久化语义变化时，
  同次更新对应权威文档。优先更新已有正文；没有能够完整承载职责的文档或发现覆盖缺口时，
  补齐真实职责、入口、依赖、关键契约和证据，不创建占位说明。
- 同一事实只有一处详细正文，其它文档可概述并链接。路径映射只做路由，不承载领域契约正文；
  adapter 引用仓库映射，不另存职责清单、版本或运行时契约。目录级规则只记录该目录的不变量与边界。
- 模块说明须能定位实现、理解职责及修改风险：包括维护路径、主要入口、调用方、实际依赖、
  数据与状态所有权、关键契约、风险、代码/测试证据及更新触发条件。按复杂度组织章节，不设固定
  标题或行数上限；普通 import 不逐项罗列，动态入口、跨层调用与实际耦合不能因精简遗漏。
- 方程或数值模块按实际职责说明未知量、连续方程或约化假设、时空离散、边界、闭合消费位置、
  shape/单位/坐标、状态发布时间和残差定义，并给出“公式/行为 → 函数 → 验证证据”的定位。
  不将该领域清单强加给无关模块，不把文档描述当成实现或测试证据。
- 纯格式、局部命名或说明性注释只核对相关代码与说明；未改变已记录事实时可不更新正文，但须
  说明依据，路径和名称变化仍修复引用。涉及行为或契约时核对相关测试证据；存储或恢复保证须核对
  实际写入与读取路径，不能从保存了 metadata 推断读取时会校验它。
- 检查完整工作区（含 staged、unstaged、untracked）以保护已有修改；模块覆盖、映射、链接及
  内容验收仅覆盖本任务及直接影响。删除或重命名时同时核对旧、新路径及其文档归属；链接检查包含
  相对路径和章节锚点，不依赖未随仓库提供的本地产物，源码外规则检查使用直接审查或一次性命令。
- 首次建立完整文档体系时，须同时完成维护中核心职责的实质覆盖和现有内容归位，再进入日常维护；
  日常局部修改不触发无关的全仓补文档。完成标准是读者能定位实现、理解依赖和契约、判断修改影响，
  并找到关键陈述的代码或验证证据。具体文档位置、映射格式与领域完成标准由仓库规定。

## 测试准入与保留边界

- 新增持久化测试只针对仓库维护的产品源码及其行为，源码范围按真实职责确定，不硬编码某个项目
  的路径。测试文件放在仓库指定位置；配置、资源和基准数据可以作为源码行为测试的输入或 fixture。
- 不为源码外的文档、规则、配置文件、算例脚本、辅助比较工具或测试支持代码自身新增持久化测试；
  这些变更通过直接审查、实际运行或一次性检查验证。作为交付产品维护的工具代码属于产品源码。
- 不保留或新增日志输出/格式/作用域专项、仅对照历史资源或迁移文件、冻结资产摘要/内部关系、
  以及仅确认可导入、构建、编译、运行或输出存在、shape、有限值、固定配置内容的纯冒烟测试。
  不用持久化扫描器或规则文本断言绕过上述限制。
- 按被测行为和断言判断，不按文件名或目录整批处理。保留有具体契约依据的数值/物理结果、梯度、
  编译复用、关键输入拒绝、字段/时间层、状态所有权、持久化与恢复等功能测试；shape/dtype 拒绝
  不等于仅查看输出形状，真实回归的数值比较和物理门槛不属于历史资产对照。
- 纯重构优先迁移既有行为用例，不因拆分、改名或增加内部抽象机械新增测试。新增用例须指出当前
  行为的具体风险和既有证据缺口；优先在既有用例中增加必要断言，具体分层与验收命令由仓库拥有。
- 不为绕过范围限制移动实现、增加测试专用包装或把禁止的检查改名为弱断言。既有测试映射只定位
  证据，不授权扩大新增范围。退役脚本时同步删除专属测试和有效引用，仍验证产品源码行为的测试按职责保留。
- 输入与基准的版本由版本管理记录，不以资产摘要替代行为验收；产品本身的完整性校验契约按其真实
  行为验证。删减测试不授权改变算法、重写基准、放宽容差或修改输入预算。
  明确记录覆盖缺口，不能把删除专项检查描述成其它测试已经完整替代，也不能把局部通过描述为全量通过。
