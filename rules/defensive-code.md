## 禁止无依据的防御性代码

适用于所有代码库和所有编程语言。信任内部已经确定的类型、字段、shape 和调用顺序，
直接实现当前需求；非法状态优先让实际消费方、标准库或框架自然报错，不为提前报错或美化信息重复校验。

- 不新增无需求依据的配置/数值合理性校验、重复 schema、字段/类型/shape 检查，以及只服务这些
  检查的 helper 或测试。边界上必要的解析、单位转换与类型转换不属于重复校验。
- 不用类型/字段探测、`getattr` / `hasattr` / `isinstance` 分支、`.get(..., default)`、
  `value or default` 等掩盖内部契约缺失；明确规定的可选项和默认值只在已有 owner 处处理一次。
- 不为假设的失败添加宽泛异常捕获、静默跳过、空结果兜底、自动修复、重试、兼容或降级。
  禁止新增裸 `except` 或 `Exception` / `BaseException` 捕获后仅 `pass` 的静默吞错。
  不得用默认值把失败伪装成成功，也不得悄悄改变数据、算法、精度、设备或执行范围。
- 不为“数值更安全”随意添加 `nan_to_num`、`clamp`、epsilon 或裁剪来掩盖输入/计算错误。
  算法定义所需的稳定计算、mask、padding、裁剪，以及普通业务条件分支，不按关键字机械禁止。
- 保留已有外部契约和有依据的外部输入/安全边界、资源清理及失败隔离。保留或新增防御分支须由
  当前调用链、明确需求或可复现故障证明：省略会产生具体错误结果、契约违反、数据损坏或资源无法
  正常结束，且消费方自然报错不足以处理；只在真正负责该边界的一处处理。
  “以防万一”“更加健壮”“未来可能需要”不构成证据。无证据就不添加，不为此额外请求确认。
- 规则约束新增和本次涉及的代码，不授权顺手清理历史代码、改变无关行为或删除仍受支持的兼容契约。

完成代码修改前，使用用户级 `review-defensive-code` skill 检查本次授权 diff，并逐项判断必要性。
Python 改动在存在 Git 基线时运行其 `scripts/check_defensive_diff.py`，限定本次文件和正确基线；
其它语言、无 Git 基线或脚本未覆盖的模式进行语义审查。不得为了检查新增依赖。
删除本次无依据分支；保留项在完成说明中简述具体故障或契约依据。候选项不是已证实违规，脚本返回 0
也不代表语义审查完成。只运行与改动相称的检查，不重复扫描或审计无关代码。

规则与 skill 不等于自动机器拦截，不得声称已在所有仓库安装 CI 或远端合并门禁。
